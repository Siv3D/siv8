# FileSystem 基盤の見直し

状態: **検討案・未採用**。対象: v0.8。
公開 API の挙動を変える項目は、影響を確認してから個別に判断する。

## 優先する課題

ゲームのアセット読み込み・一覧取得・保存で、同じパスが同じ対象を指すことと、
不要な変換・問い合わせを減らすことを優先する。

| 課題 | 確認できている問題 | 対応方針 |
|---|---|---|
| パスの解釈 | macOS では `directory\data.bin` の Exists が true でも Copy が失敗する。存在確認は `\` を `/` に置換し、Copy は置換しない | FileSystem と Reader / Writer が同じ対象を扱うようにする。区切り文字の契約と既存利用への影響を先に確認する |
| 列挙でのリンク名 | macOS の DirectoryContents はリンク名をリンク先へ置き換える。同じ対象への別名が同じパスとして返る | アセット一覧でエントリ名を扱えるよう、列挙とリンク解決の関係を見直す。現行 FullPath の意味まで一括変更しない |
| 重複処理 | macOS の DirectoryContents は各項目で文字列を往復変換し、FullPath を呼ぶ | 現在の戻り値・失敗時の挙動を維持できる範囲から、操作内でパスや取得済み情報を再利用する |

根拠は [共通実装](../../../Siv3D/src/Siv3D/FileSystem/SivFileSystem.cpp)、
[macOS / Linux 共通実装](../../../Siv3D/src/Siv3D-Platform/macOS_Linux/Siv3D/FileSystem/SivFileSystem_macOS_Linux.cpp)、
[macOS 実装](../../../Siv3D/src/Siv3D-Platform/macOS/Siv3D/FileSystem/SivFileSystem_macOS.mm)。
OS ごとの挙動は [診断プログラム](../../../Test/Manual/FileSystemReview.md) で照合する。

## 進め方

1. **互換性を保つ内部改善。** ネイティブ形式へ直接変換し、不要な中間文字列を減らす。
   列挙の重複を調べ、効果のある箇所だけを変更する。
2. **通常操作の不整合を解消。** 区切り文字と列挙時のリンク名は、変更前後の具体例で
   互換性を判断する。Reader / Writer、資源一覧など、変更対象の利用箇所も確認する。
3. **代表的な負荷で評価。** アセット一覧の取得と通常ファイルの属性取得を、
   同じホスト・同じ Release 設定・同じデータで比較する。
   時間だけで原因を判断できない場合に、割り当てや OS 呼び出しを追加で調べる。

共有コードの変更ごとに macOS の全自動テストを実行し、Windows の結果を適宜確認する。
性能の閾値は通常の自動テストに含めない。作業状況は [TODO.md](../../../TODO.md) で管理する。

## 必要性が出たときに扱う項目

新しい公開 Path 型、詳細エラー API、属性キャッシュ、特殊ファイルや不正入力の
網羅的な規約は、具体的な利用上の不足や不具合が確認された時点で検討する。
内部のエラー情報も、失われることで誤動作する箇所に必要な範囲で保持する。

公開ヘッダには利用判断に必要な契約と例を記載し、実装の経緯や計測手順は追加しない。
