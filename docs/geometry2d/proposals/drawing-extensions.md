# 2D 描画の拡張提案

状態: 未採用の設計候補。対象リリース、実装時期、公開 API は未定。

ゲーム・UI・図解で繰り返し使う表現を、短い記述と予測できる描画コストで扱うための提案。
既存の図形型、LineStyle、JoinStyle、保存メッシュを組み合わせ、
新しい型や設定を必要とする範囲を絞る。

## 描画スタイルと矢印

| 機能 | 主な用途 | 設計の方向 | 判断に必要な確認 |
|---|---|---|---|
| 四隅別の角丸枠の LineStyle | 非対称なカード、タブ、選択枠 | `Rect` / `RectF::drawRoundedFrame()` で LineStyle を受け取り、輪郭全体に破線を配置 | 半径 0、角の干渉、内側が消失する枠、四隅同半径での RoundRect との整合 |
| Shape2D / Polygon の枠の LineStyle | 地図、領域の強調、図形の装飾 | 保存された輪郭に距離基準で破線を配置 | 外周と穴の位相、輪郭の向き、鋭角での見た目、長い輪郭の準備費用 |
| 楕円弧の片端・両端矢印 | 軌道、回転の説明、遠近感のある図解 | Ellipse の円弧に、曲線上の根元から先端へ向ける矢じりを接続 | 根元探索、短い弧と大きな head、太い内側オフセット、全周の端点一致 |
| LineString・図形枠の JoinStyle | 折れ線、経路、角のある領域 | miter・bevel・round を選択し、線端とは独立して指定 | 鋭角、折り返し、閉じ目、自己交差、半透明、曲線近似点と本来の角の区別 |

### 閉じた輪郭の破線

周長に整数個の周期を収め、直線・円弧の境界や閉じ目で模様を再開しない構成とする。
位相の基準点と向きを明示し、Polygon の穴を含む場合は各輪郭の周期と位相を定義する。
寸法や線幅の変化で周期数が切り替わる場合の見た目も比較する。

四隅別の角丸枠は、正規化した内外輪郭と距離基準を整合させる必要がある。
半径の消失や内側の塗りつぶしへの退化を含め、通常の枠と同じ入力で比較する。
任意多角形では、短い破線が角をまたぐ際の変形や重なりが残るため、
滑らかな輪郭と同じ品質を一律に保証しない。

設計の参照先は [破線の距離配置と制約](../dashed-drawing.md)、
[四隅別の角丸描画](../rounded-drawing.md#independent-corner-rectangles)。

### 楕円弧の矢印

head の寸法と向き、短い経路での縮小・省略を [曲線矢印](../bezier-drawing.md#curved-arrows)と揃える。
円弧の非一様拡大では軸と head の幅も変わるため、楕円上で位置と法線を直接求める。
根元の探索と輪郭の分割には処理上限を設け、全周では先端と始点を一致させる。

### 結合部の形

LineString の角と、Bezier / Spline の近似に使う分割点を区別する。
曲線の品質設定を変えるだけで目立つ角が増えない設計が必要になる。
Image と GPU で join の幾何的な意味を揃えつつ、合成や自己交差処理の費用は別に評価する。
Image 側の検討事項は [TODO](../../../TODO.md) にまとめる。

## 形状生成

| 機能 | 主な用途 | 最小の対象範囲 | 設計上の課題 |
|---|---|---|---|
| 角丸ドーナツ扇形 | ラジアルメニュー、円グラフ、円形ゲージ | 内外半径・開始角・sweep・角丸半径で指定する塗り | 狭い扇形での角の干渉、内半径 0、全周への変化、角度と距離による空隙の違い |
| 二曲線間の帯 | 川、リボン、流量図、面グラフ | 二つの境界曲線と端の接続線から、再利用可能な Mesh2D を生成 | 対応点の選び方、strip の反転、分割品質、自己交差を許す範囲 |
| 滑らかな角を持つ矩形 | UI のカードやアイコン | 直線部を残し、角半径と接続の滑らかさを指定する塗り・保存メッシュ | smoothing の意味、狭い辺での形状調整、通常の角丸・SuperEllipse との差 |

角丸ドーナツ扇形は、指定した扇形の内側で角を削る形とする。
端点から半円が張り出す Round cap とは異なる。
角丸半径を帯幅と角同士の距離で制限し、幅 0、sweep 0、内半径 0、全周の規則を先に決める。
図表のデータ配置や面積補正は呼び出し側の責務とする。

二曲線間の帯は、中心線からの法線距離で幅を指定するストロークとは異なる。
外周が単純でも、任意の点対応で安全な strip を作れるとは限らないため、入力条件を絞る。
構築先の容量を再利用できる形を基本とし、strip の頂点順を Shape2D の外周として扱わない。

滑らかな角の矩形は、曲線構成とパラメータの意味を確定してから API を決める。
まず塗りと保存メッシュで用途を確認し、等距離の枠や影は必要性を個別に判断する。

## NinePatch（9-slice）

状態: RenderTexture の描画先切り替え実装後に着手する保留項目。公開 API と初期範囲は未確定。
伸縮型の描画は既存のテクスチャ付きメッシュ経路だけでも実装できるが、作業順序として後にまとめる。
未完了作業は [TODO](../../../TODO.md) で追跡する。

v0.6.16 との互換性を前提にせず、既存の Texture / TextureRegion と分割情報を保持する
軽い値型 `NinePatch` を候補とする。テクスチャ資源は共有し、コピー後の分割・表示設定は独立させる。
分割位置は構築時に検証し、UV 境界を準備する。

| API 候補 | 用途・設計条件 |
|---|---|
| `NinePatch(source, slice)` | source は Texture / TextureRegion。slice は全辺共通の幅、または `Slice` の top / right / bottom / left |
| `draw(rect, color)` / `drawFrame(rect, color)` | 全体、または中央を除いた八領域を描画。乗算色の既定値は白 |
| `setBorderScale(scale)` / `borderScale()` | 元画像の分割位置を保ち、表示する角・辺の倍率を指定。既定値 1 |
| `innerRect(rect)` | 実際の枠幅を反映した中央パッチの領域。文字などの余白は GUI 側で調整 |
| `minimumSize()` | 角を縮めずに描ける最小サイズ。これより小さい描画先も扱う |
| `source()` / `slice()` / `isEmpty()` / `operator bool()` | 素材・設定の読み取りと有効性の確認 |

分割単位は TextureRegion の現在の size の絶対値に合わせ、反転した入力では見た目の
上・右・下・左を基準とする。元画像の分割と表示時の枠倍率を分け、高解像度素材にも対応する。
初期範囲の候補は伸縮描画、枠のみの描画、枠倍率、中央領域の取得。

小さい描画先では、表示予定の四辺を共通倍率
`min(1, W / (L + R), H / (T + B))` で縮め、角の縦横比を保つ。
分母が 0 の項は制限に使わない。描画と innerRect で配置計算を共有する。
描画先の幅・高さが 0 以下なら描画せず、面積 0 のパッチも省略する。
分割幅 0 による 3-slice、全辺 0 による画像全体の伸縮、枠倍率 0 による中央のみの描画を検討する。
空の素材、負の分割幅、元画像の中央幅・高さが 0 以下の場合は空の構築結果とする案。
非有限値の前提、空の場合の戻り値、反転と非対称な分割の組み合わせも実装前に確定する。

伸縮型は最大 16 頂点・18 三角形、枠のみは最大 16 三角形を固定長 CPU 配列で作り、
既存の addMesh2D へ一度に投入する構成から評価する。NinePatch 自身の描画準備では
ヒープ確保を行わず、現在の描画変換・色・シザー・サンプラーを利用する。
隣接パッチの境界座標を共有し、半透明、縮小、アトラス、Nearest / Linear、描画状態を検証する。
九個の四角形を個別に描く方法と CPU・実バックエンドの双方で比較し、直接書き込みは測定に基づいて判断する。

[旧版の実装](https://github.com/Siv3D/OpenSiv3D/blob/v0.6.16/Siv3D/src/Siv3D/NinePatch/NinePatchDetail.cpp)は、
タイリングする上・下・左・右・中央を最大 5 枚の RenderTexture に切り出して保持する。
Image 入力は CPU で切り抜き、Texture 入力は Shader::Copy で転写する。
Repeat サンプラーは元テクスチャ全体を繰り返すため、部分領域の反復にはこのような別の処理が必要になる。
再開時は切り出しキャッシュ、幾何分割、専用シェーダを比較し、タイリングの採否と段階分けを決める。
反復倍率、端の切り方、素材更新時の扱い、準備費用、メモリ、アトラスと mipmap のにじみを評価する。

## Trail に依存する可変幅ストローク

先細りの軌跡、斬撃、筆線、レーザーを対象とする。
Trail 系の実装で幅指定・接合・半透明・頂点生成を評価してから、
LineString / Bezier2 / Bezier3 / Spline2D に適した公開 API を設計する。

- 始終幅、点ごとの幅、途中の幅変化を比較する。補間を媒介変数・累積弧長・時間のどれに結び付けるかを区別する。
- 幅 0 の先端、負の幅、重複点、急な幅変化、折り返し、閉じ目を定義する。
- 左右の境界を含めて分割品質を評価し、内側の反転と半透明の重なりをどこまで許容するかを決める。
- 作業領域と生成済み頂点を再利用し、テクスチャ座標との関係を整理する。
- 一定幅の描画へ一律に補間・検査費用を加えず、自己交差の完全な除去を前提にしない。

## 需要を確認してから設計する機能

| 機能 | 検討を進める条件 | 比較する手段 |
|---|---|---|
| 回転角丸長方形の直接描画 | 多数の独立した部品の回転で、記述量や描画状態の変更が問題になる | Transformer2D、保存 Polygon、直接描画 |
| 角丸正多角形の直接描画 | 頂点数・半径・角丸が頻繁に変化し、形状の再構築が負荷になる | `Shape2D::Ngon(...).rounded(...)` の生成・保存と直接生成 |
| 螺旋の点列生成 | 回転数と始終半径を指定する作例が繰り返し必要になる | 保存先を再利用する LineString 生成とアプリ側の計算 |
| 複合パスと塗り | 複数輪郭、穴、直線と曲線を一体として編集・保存する必要がある | 経路データ、分割、塗り規則、三角形分割、メッシュキャッシュの責務分離 |

複合パスでは NonZero / EvenOdd、交差処理、輪郭の向きを明示する。
Spline2D の曲線分割を利用できても、塗り規則や複数輪郭の処理は別に設計する。
SVG 文書全体の読み込み、テキスト、filter は対象範囲を広げるため独立した機能として扱う。

## 採用の判断基準

- **使う場面を示す。** 呼び出し側の短いコードと実行可能な作例で、既存手段に対する利点を確認する。描画スタイルの拡張は既存の型と命名を優先する。
- **見た目と処理量を同時に決める。** 半透明、拡大、短い経路、幅 0、全周、内側の消失を試す。許容する重なりや省略条件を明示し、重い修復処理を暗黙に組み込まない。
- **直接描画と保存形状を比較する。** 動的な生成、静的な反復、多数の小形状、少数の大形状を分ける。必要なら保存先を再利用する生成処理を設ける。
- **性能の測定範囲を明示する。** 形状構築、CPU の描画投入、実バッファへの転送、GPU 実行を分け、確保前後も比較する。[転送と測定の指針](../../renderer2d/README.md#measuring-cpu-writes-to-upload-buffers)に従う。
